# @red-cup-engineering/metrologic

The mathematical library consumed by the 561 Group's higher semiotic and agent
packages: pure operations and finite readouts over articulations, predications,
FOUR charges, closures, and their derived projections. The primitive research
direction is **relationlessness → source-generated articulation → open Fregean
predication → independently told evidence/FOUR → positing → settling**. The
code available here implements selected downstream mathematics; its current
FOUR and categorical carriers are not proofs that the earliest generative
arrows have been constructed.

This package is ESM-only, Node >=20, and organized by explicit subpath exports.
It does not provide a broad default import.
Consumers should import the math surface they actually descend through.

Metrologic is the data layer's mathematics, currently source-owned at
`computer-data-engineering-services-section/lib/metrologic` while its complete
standalone-root source is carried on the extraction branch
`split/metrologic-standalone-20261017`. The root package's mathematical imports
are FOUR, exact numbers, closure regimes and selected JSON presentation functions;
Metrologic has no direct SignCell, NI/content-address or agent faculty dependency.
Its primitive `./mark` is an uninterpreted schematic carrier, not a digest or an
equality oracle. The Laplacian, PyMetrologic, and enriched-category research
applications live under computer-math-system; proof-assistant integration lives in
computer-proofing-system.

## Source-generated Mark and observational identity

`@red-cup-engineering/metrologic/mark` supplies the single schematic Mark
shape. Its `value` is any presented datum, with no NI name, witness strength,
or primitive equality. SignCell imports that schema and implements the
technological admission and address space downstream.

`./articulation/predicating/equality` now requires a caller-supplied
comparison with a trace, test family and either an identification witness
or separating obstruction. Unknown is not false and payload-byte coincidence
is not `Quot.sound`.

The abstract `obstruction/settling` filtration receives its observational
`keyOf` explicitly when treating opaque objects as equivalent. Without
an admitted relation, distinct object occurrences remain distinct.
SignCraft supplies SignCell's coincidence relation when projecting native
SignCells to this generic mathematics. `./chu` similarly treats reference
positions as distinct unless its consumer supplies `samePoint`/`sameState`.
These are *conditional* constructions downstream of the originating act,
not proofs that exclusion itself generated the observations.

## Kinematic Space and canonical diamond-bead threading

`@red-cup-engineering/metrologic/articulation/predicating/positing/settling/analysis/causal`
exports `kinematicDiamondSpaceOf({eventCount,edges})`: a bounded (at most
32 source events), topologically indexed causal DAG projection to the finite
space K(C) of strictly reachable endpoint pairs. `sequencing` is endpoint
sequencing, **not** interval nesting or shared timestamps. Distinct signed
source evidence events remain distinct in the consuming SignCraft replay.

The returned `beadThread` is the already-proved
`Obsmetrologia.CausalSets.BlackHoles.diamondThread` readout: one canonical
`{pointIndex,inPort:false,outPort:true}` pass for each diamond point.
Every pass obeys the local `PortGraph.legal_iff_distinct` law.
`beadThreadAdjacency` is the *same immutable relation object* as
`sequencing`, conforming to
`DiamondBeads.sequencingBeadAdjacency_thread`. This is **not** a separate
bead-weaving graph or another closure engine. Source tests check the
local-port and adjacency laws for all 1,100 forward DAGs through five events.

The complete `beadThread` list consists of **local, individually legal
passes**; those points need not form a single sequencing-compatible path.
`kinematicBeadStrandsOf(space)` first rederives the full causal-diamond
geometry and rejects mismatched/missing arrows or altered passes. It then
computes a deterministic **minimum disjoint path cover** using bipartite
maximum matching on the actual endpoint-sequencing relation. It returns
`strands` (lists of the original local passes),
`matchedSequencing`, `strandCount`, and `requiresMultipleStrands`.
Every diamond is covered exactly once and every adjacent pair within a
strand is genuinely sequenced. The number of required mathematical strands
is the **maximum antichain width**, not a count of physical strings.
The 1,100 small-DAG regression cases independently enumerate antichains
and compare the exact width; the three-event chain already needs **two**
strands because its long interval overlaps the short ones.

The returned `maximumAntichain` is an **explicit lower-bound witness**, not
just an asserted numeric width. Metrologic extracts it from alternating
reachability in the maximum matching, while the existing `strands` are an
upper-bound witness. `kinematicBeadCoverAdmits(space, cover)` independently
checks that every bead pass occurs once, that all transitions are actual
sequencing, and that the alleged antichain contains distinct pairwise
incomparable points with exactly the same cardinality as the strand cover.
The checker **does not run matching**. Equality of the two bounds certifies
minimum cardinality for the supplied finite K(C), without claiming external
witness authenticity or any physical material realization. The 32-event
linear order yields 496 intervals and a concrete 256-member antichain
crossing the central cut.

This mathematical carrier does **not** supply a connected physical string,
per-bead repeated occupation, independently separated contact/cell/visible
graphs, bead geometry, a material realization, a proof of external SignChain
rule licenses, or Lean-kernel admission. The remaining fields for
`SequencingDiamondBeadPayload.toBeads` must be supplied and qualified
separately; they must not be inferred from `beadThread` length or the
`causalRanks` schedule.

### Finite Kinematic Space transport has an exact morphism criterion

`kinematicDiamondTransportOf(sourceSpace, targetSpace, eventMap)` maps
each diamond `(a,b)` to `(f(a),f(b))` **if and only if** the total
listed-event map `f` preserves every strict source causal pair. That
condition is necessary because every strict pair is an admitted diamond;
it is sufficient because equality and strict precedence preserve
endpoint sequencing. The endpoint construction respects identities and
composition, so it is functorial on this category of finite causal sets
and strict-precedence-preserving maps. No reflexive-order-only map is
silently promoted to a strict map.

The executable returns exact indexed `eventMap` and `pointMap`,
`identifiedPoints`, `newlyComparable`, `unmappedTargetPoints`, and
whether the result embeds the source point order into the target or
covers the target points. These record **information lost**, not a failed
calculation: incomparable source events may be identified, and
incomparable source diamonds may become sequenceable after a target
gains causal relations. **Maximum-antichain and minimum-strand
certificates do not automatically transport under these maps.** When the
induced diamond map is a genuine **order isomorphism** (bijective on points,
preserving and reflecting sequencing), `kinematicBeadCoverTransportOf`
instead maps the already-admitted source strands and maximum antichain
directly onto target points, independently admits the target dual bounds,
and returns `metrologic.kinematicBeadCoverTransport.v1`. This does **not**
rerun maximum matching. The order isomorphism need not be a bijection on
underlying events: adjoining a disconnected event, for example, leaves K(C)
unchanged. Non-isomorphisms and forged source certificates refuse. A general
strict K(f) can still transport its points even when an optimal bead cover
cannot be reused.

To reduce repetitive K(C) reconstruction, the implementation privately
recognizes only immutable canonical spaces and admitted covers originally
created by its own provider; neither a copied wrapper nor a JSON clone
inherits that trust. Serialized inputs undergo full canonical validation
and dual-witness checks. Private typed-array sequencing lookup replaces
repeated string-keyed graph scans, while the full independent checker
remains available through `kinematicBeadCoverAdmits`. Certificate transport
avoids an optimization search; whether it is faster in a deployed workload
must be measured separately, not inferred from that fact.

The regression suite checks 1,100 identity carriers, 2,067 total
small-DAG event maps (536 admitted, 1,531 refused) against an independent
strict-reachability oracle, composition, non-injective lawful maps,
newly introduced comparabilities, sparse-map refusal and forged source
geometry. These are executable finite comparisons alongside the
general endpoint proof, **not** a declaration-specific Lean-kernel
admission or a physical causal interpretation.

## Bead routing: actual port walks and local occupation

`@red-cup-engineering/metrologic/articulation/predicating/positing/settling/analysis/port-thread-routing`
is the data-owned **finite material port-routing** API, distinct from
`analysis/causal` and its acyclic K(C) diamond sequencing. The former
works with named rigid bead units, explicit paired ports for each hole,
and explicitly supplied **directed external connector segments**.
`portThreadRouteOf` checks the complete word of internal hole passes
and external connectors including an explicit closed-loop join. It
retains repeated visits, exact traversed thread segments, local
per-bead **and per-hole** pass counts, and the existing
`portGraph.condensate` FOUR readings at those local counts.

```js
import {
  minimumPortThreadRouteOf, portThreadRouteOf,
  closedPortThreadFeasibilityOf, coveringPortThreadRouteOf,
} from
  "@red-cup-engineering/metrologic/articulation/predicating/positing/settling/analysis/port-thread-routing";

const p = (beadId, port) => ({ beadId, port });
const beads = ["a", "b", "c"].map(id => ({ id, holes: [["in", "out"]] }));
const links = [
  { from: p("a","out"), to: p("b","in") },
  { from: p("b","out"), to: p("c","in") },
  { from: p("c","out"), to: p("a","in") },
];
const result = minimumPortThreadRouteOf({ beads, links, closed: true });
// result.minimalPassCount === 3; each bead has occupation 1.
const possible = closedPortThreadFeasibilityOf({ beads, links });
const constructive = coveringPortThreadRouteOf({ beads, links });
// possible.feasible === true; constructive.passCount === 3.
// A positive feasibility decision does not claim minimum thread length.
// To independently receive a proposed walk:
const receipt = portThreadRouteOf({
  beads, links, closed: true, requireEveryBead: true,
  passes: result.thread.map(({beadId,enter,exit})=>({beadId,enter,exit})),
});
```

`minimumPortThreadRouteOf` uses a bounded exact breadth-first
search to minimize **the number of bead-hole passes** covering all
listed beads, not cord length, weighted turns, material tension, or the
Demaine/Kirkpatrick/Lin graph-tightening objective. A closed port-route
may repeat a bead; a causal K(C) sequencing graph cannot supply the
required closed directed walk unless independent material connectors
are actually admitted. The bounded solver refuses unsupported sizes
(greater than nine beads, sixty oriented local passes, ninety-six
external links, or its 300,000-state budget) instead of calling a
budget exhaustion a mathematical impossibility.

**New finite closed-walk characterization and constructive receiving.**
`closedPortThreadFeasibilityOf({beads,links})` builds the graph of
**oriented legal hole passes** (one pass state per oriented hole) and adds
a directed edge only for an explicitly listed external exit-to-entry
connector. A nonempty closed route visiting every bead exists **if and
only if** one cyclic strongly connected component of this state graph
contains a pass of every listed bead. Necessity follows by following
any valid closed word around its visits; sufficiency follows by
concatenating directed paths between each bead's representative in
that component and returning to the start. An isolated singleton
without a self-loop is not a cycle.

The feasibility result exposes the complete finite strong-component
coverage, the number of cyclic components, the maximum number of
beads covered by any one cyclic component, and the actual covering
pass indices when one exists. This is a mathematical **yes/no decision**
on the bounded carrier, *independent* of how expensive a particular
route would be to construct.

`coveringPortThreadRouteOf({beads,links})` then builds an actual
possibly repeated route and **replays it independently** through
`portThreadRouteOf`. It can return `route-search-budget-exceeded` or
`route-pass-budget-exceeded` even when the exact feasibility report
says `feasible: true`. It must never equate those resource limits
with geometric impossibility. The former unit-cost minimum search
still handles at most nine beads; the new strong-component decision
accepts up to 4,096 beads, up to 24 paired holes per bead, and at most
131,072 explicitly listed external connectors. The oriented transition
graph is indexed once from ports rather than reconstructed with a
pass-by-connector nested scan.

`test/port-thread-connectivity.test.mjs` checks the necessary-and-
sufficient criterion against an independent 64-graph directed-word
enumeration and 256 mixed-orientation connector graphs with an
independent Floyd–Warshall oracle. It also checks a 1,500-bead closed
ring, a branching route that must revisit its hub, different holes
on the same repeatedly visited bead, a one-bead two-pass cycle,
disjoint strongly connected components, and strict causal K(C)
sequencing without invented material closure.

The construction establishes neither Demaine–Kirkpatrick–Lin
graph-tightening's required junction connectivity nor the later
turn-cost, weighted thread length, friction, collision,
materialization, or community-specific authorization conditions.
Those are separate qualifying interfaces, not silently assumed
results of this strongly connected component theorem.

**Kinetic, dimensioned thread-length optimization.** The same source-owned
`port-thread-routing` export now also provides
`materialPortThreadRouteOf` and `minimumMaterialPortThreadRouteOf`.
The latter solves the **exact additive minimum-length** objective on the
same bounded nine-bead pass-state carrier, instead of minimizing the
number of bead-hole passes. It is a separate objective, not a rival
port graph or a duplicate settlement engine.

Every bead must provide `holeLengthsUm`, an array of **positive
safe-integer micrometre estimates**, in the same order as its paired
`holes`. Every allowed directed external connector must provide
`lengthUm`, a **nonnegative safe-integer micrometre estimate**. There
are no assumed, zero-filled, or distance-inferred defaults. The
optimizer uses nonnegative-weight Dijkstra on
`(firstPass, lastPass, visitedBeadMask)` and counts each repeated
hole passage and connector, including the closing connector. It
computes all total lengths using `BigInt` and serializes results as
decimal integer strings. The independent `materialPortThreadRouteOf`
replays an emitted route through actual named ports and returns
`holePassLengthsUm`, `connectorSegmentLengthsUm`,
`holeLengthUm`, `connectorLengthUm`, and `totalLengthUm`.
A non-calibrated input explicitly yields `lengthsCalibrated: false`.

**Independently check the kinetic optimum.** On bounded queries, pass
`includeOptimalityCertificate: true` to
`minimumMaterialPortThreadRouteOf`. The optional
`optimalityCertificate` contains a threshold `L` (as an exact decimal
micrometre string) and a finite collection of lower-bound states
`(start, last, visitedMask, boundUm)`. The independent
`materialPortThreadOptimalityAdmits(spec, certificate)` first
replays the proposed route and its exact cost, then checks:

- every possible initial pass with cost less than `L` has a claimed
  lower-bound state no greater than its actual starting cost;
- every connector transition from a certified state whose proposed
  accumulated cost would be less than `L` leads to another certified
  state with no larger lower bound;
- no certified all-covered state can reach the terminal goal (including
  a closing connector when required) for less than `L`.

By induction, **any hypothetically cheaper word would have to stay
inside these checked states and arrive at a forbidden cheap terminal**.
The actual admitted word of cost `L` is the matching upper bound.
Thus `optimalityAdmission.lowerBoundUm` and `upperBoundUm` are
equal independently of the solver. This is a genuine finite
**kinetic-proof receipt**, not a self-labelled optimal route or a
Lean-kernel certificate about the world.

The optional certificate is capped at 10,000 states to bound receipt
size. A request that would exceed that limit refuses as
`material-optimality-certificate-budget-exceeded`; retry without the
optional certificate to obtain an optimized route without falsely
claiming independent proof. The test suite checks all 128 tiny
open/closed weighted instances with this independent verifier and
rejects tampered, incomplete and duplicated frontier states.

For a concrete falsification of pass-count optimality, give three
beads A, B, C unit-cost hole passages, length-1 connectors A↔B
and A↔C, and length-100 connectors B↔C. The original pass-count
solver returns a three-pass covering cycle costing 105 micrometres.
The length solver correctly chooses A→B→A→C→A, which is four
actual bead passes and a last-to-first closing connector,
costing only **8 micrometres**. Neither solution implies a
physical cord layout, safe tensile load, friction or measured
diameter.

The additional `test/port-thread-material-length.test.mjs`
enumerates all 64 three-bead directed graphs under both open and
closed weighted objectives, compares with an independent explicit
thread-word oracle, checks a cheaper multi-hole alternative,
independently replays repeated connector costs, verifies
`BigInt` totals above `Number.MAX_SAFE_INTEGER`, and refuses
unpriced, fractional, negative or unsafe-integer lengths.
The bounded optimizer returns `material-route-search-budget-exceeded`
rather than falsely claiming graph-theoretic impossibility.
Graph-scale closed-port feasibility remains the independent
strong-component decision and is not limited by the length optimizer.

Global `passCount` and local occupation are **not interchangeable**.
For a three-bead cycle with one pass at each bead, the global
`condensate(3)` is the held-both FOUR reading, but **none** of its
three individual bead occupations is held-both. Branching routes that
revisit the hub can have a genuinely locally held-both reading.
The presence of such a reading **does not establish physical
superjamming**: contact, friction, placement, stiffness, surface
visibility, machine feasibility, and cultural authority require
independent evidence. This API does not synthesize these missing
graphs or assert authorization to fabricate a physical object.

The test `test/port-thread-routing.test.mjs` exercises the real
consumer interface, independent explicit-route replay, local and
per-hole counts, failure cases, and all 128 open/closed scenarios
over the 64 directed port-link graphs with three beads against an
independently enumerated route-word oracle.

## Signed formal contexts and supported implications

`@red-cup-engineering/metrologic/closure/formal-context` provides
`withSignedAttributes(ctx)` to extend an existing context's declared alphabet
to its positive and negative attributes without adding incidence rows.
`makeContext` keeps its positive-only default when no denial rows are supplied.
A known but unobserved denial then has empty extent; an unknown attribute
continues to fail carrier admission.

`lawfulBasis` compiles its exact supported implication family using only
actually incident columns. This preserves implication closure for every seed,
including contradictory seeds, while preventing unused negative columns from
doubling the exponential compilation dimension. Full `dgBasis` and Galois
prime operators continue to use the complete declared alphabet. The
preservation argument is in
[specifications/formal-context.md](specifications/formal-context.md).

## Finite numerical conductance

`@red-cup-engineering/metrologic/articulation/predicating/positing/settling/analysis/numeric-laplacian`
owns the numerical Laplacian, nonnegative edge energy, symmetric eigenvalues,
least positive spectral gap, and spectral distance bound over finite indexed
graphs. Its input is a symmetric nonnegative weight matrix and, where needed,
a finite scalar vector. Named attributes and evidence projection remain in
SignCraft's conductance field.

The numerical solver normalizes scales and derives nullity from positive-edge
connectivity. It refuses nonconvergence and unresolved positive gaps instead
of treating small conductances as zero. `numericRefusalBound` cancels uniform
weight scale before computing the quotient, including when a raw energy or
gap would overflow or underflow. Exact integer/rational graph operations
remain in `analysis/laplacian`. The complete component contract and numerical
limits are in [specifications/numeric-laplacian.md](specifications/numeric-laplacian.md).

## Finite numerical probability laws (distinct from FOUR knowledge)

`@red-cup-engineering/metrologic/number/finite-law` owns three
source-agnostic finite numerical operations: linear expectation over one
normalized joint probability vector, a minimum/maximum linear expectation
over an assumed total-variation ball on that SAME simplex, and an upper-tail
mean with fractional boundary mass. The implementation uses compensated
binary64 sums and source/destination mass ledgers to avoid losing later
transfers after a sub-ULP probability movement.

This is the **shared numeric mathematical operator**, not another event,
market, forecast, account, trade or SignCell carrier. Probabilities are
conditional assumptions, never FOUR supporting/opposing witnesses or a
substitute for a source-clock/provenance record. The caller continues to
own its observed worlds, net payoff units, information filtration,
confidence claims, feasible action menu and authorization. For example,
a financial caller may send per-world total *portfolio* payoff values;
Metrologic knows nothing of Kalshi contracts, Alpaca shares, GMX collateral
or the issuer that supplied a forecast.

The finite transport proof obligation and expected-shortfall variational
law belong upstream to Obsmetrologia. JavaScript does not emit a Lean theorem
receipt or guarantee that an empirically unknown distribution lies in the
assumed ball. Scientific verification requires an actual checked theorem and
an independently qualified empirical uncertainty model.

## Use From Computer

Computer packages should name their descent explicitly:

```js
import { settle } from "@red-cup-engineering/metrologic/bilattice";
import { existsAlong } from "@red-cup-engineering/metrologic/hyperdoctrine";
import { place, styleFor } from "@red-cup-engineering/metrologic/readout";
import { chuSpaceOfMatrix } from "@red-cup-engineering/metrologic/articulation/predicating/positing/logic/linear-logic-chu";
```

Do not rederive bilattice, hyperdoctrine, readout, or Chu operations locally.
Extend the defining mathematical module when a consumer needs another operation; consumers import that module directly.
