# Native declared-type state checkpoint

## Requirement and owner allocation
The Still Willow Reach receiver needs its admitted native records and heads to survive intermittent machine availability, with byte-exact recoverability and original addresses and head timestamps. Existing SEAVT owns the native persistence law. The checkpoint belongs there, not in a runtime launcher, journal writer or a new persistence format. The caller owns exclusive/quiescent access for the entire synchronous operation and independent custody of the resulting native tree. This operation cannot establish remote custody or process exclusion.

## Contract
- CP-1: Require an explicit nonempty unique list of at most 32 lawful native types and caller quiescence acknowledgment before reading or writing. Acknowledgment is an environmental obligation, not proof of a lock.
- CP-2: Read only selected native data/records and data/state directories. Never capture logs, credentials, unrelated types or client files. Reject links and nonregular entries in selected paths.
- CP-3: Exhaust strict native record and head discovery, retaining unheaded records. Validate addresses and head representation through native APIs.
- CP-4: Inventory every selected native file before discovery and after transfer. Refuse success on any source inventory change. Preserve source on failure.
- CP-5: Use native put and writeHead into a fresh empty destination, retaining original addresses and head.at. Require exact path/size/SHA-256 equality before reporting capture integrity. If native rewrite normalizes a noncanonical source, refuse exact capture rather than invent a raw writer.
- CP-6: Report causal obligations separately from byte integrity. Inspect every selected record's native causes and every head frontier with referenceOf. Classify absent declared references as missing and undeclared references as external obligations; do not load external types or require remote availability. Complete means no unresolved selected causal obligations; partial capture must never be called semantically complete.
- CP-7: Verification performs the same strict discovery, source/checkpoint before/after inventory and exact path/digest checks without writes. No success marker inside state. A returned result is evidence only for the observed trees and declared caller quiescence.
- CP-8: Interrupted prepare leaves original source untouched and destination partial/uncertified. A later verifier may establish a fully written tree, but prepare never resumes or overwrites a nonempty target. Recover by retaining partial evidence and choosing a fresh destination.

## Algorithm and boundedness
Canonical sorted type list; native layout functions select directories. Bounded recursive file inventory (no symlinks), strict record/head iteration, semantic record identity checks, collect native reference obligations, native writes followed by independent digest inventory. Refuse on file/count/byte bounds instead of unbounded traversal. No filesystem-wide snapshot claim: the caller's quiescence is essential; before/after equality cannot detect an ABA mutation.

## Derived tests
Complete round trip and repeated read-only verify; original addresses and timestamps; unheaded records; missing selected cause and external type obligation without data loss; malformed native row/head; extra path; byte corruption; nonempty destination; overlapping roots; caller quiescence absent; empty lawful selected type; interruption during native writes; concurrent mutation between inventories; source unchanged on failure; no logs copied; path links refused. Test-only fault injection must exercise the actual write/inventory boundary without adding public callback authority.

## Existing mechanism comparison
SEAVT directoryRemote/pull exchanges only heads and the records they reach, synthesizes destination head time, merges frontiers, and can converge with missing remote records. It does not retain unheaded records, original head time or byte-identical files, so it is not a checkpoint. checkNativeTypes fully exhausts strict each/heads but its causal walk starts only from heads and rejects absent causes. It can certify fully complete captures, but is not the capture or the partial-causality reporting contract. Native each/get/referenceOf provide strict record/address and edge validation; validating every selected record's direct references establishes selected closure without dereferencing undeclared types. Lifecycle/start-stop/install ownership remains distinct from persistence and cannot substitute for a state checkpoint. No package install hook is introduced.

## Callable interface and result
The package exports `./checkpoint` with synchronous `prepareNativeCheckpoint({source, destination, types, quiescent})` and `verifyNativeCheckpoint({source, checkpoint, types, quiescent})`. Both roots must already exist, be owned absolute canonical real directories with real ancestry, and be disjoint. `quiescent: true` acknowledges caller exclusion of all source and target writers, rename actors and cleanup actors through the call. It is required for both roots; it is not a new lock or a proof that another process stopped.

Success returns `{captureIntegrity:true, types, counts, causality, files, bytes}`. `types` is sorted; `counts[type]` contains records and heads. `files` is the exact sorted list of relative native paths with byte sizes and SHA-256 digests, suitable for a separate receiver's custody receipt, not a new persistence format. `causality` contains `complete`, `missing` (declared type/id references absent from selected state) and `external` (type/id references beyond declared scope). Complete is scoped native causal closure only, not application/business semantic validity. No return data claims remote custody, general backup completeness, locked publication or crash survival beyond the selected native durable writer's platform contract.

The capture retains native bytes through native `put` and `writeHead` with `durableRoot: destination`; current Data owner 1d34cc49bd6309915985209e19a5d6ff56819421 supplies these strict durable operations through its existing computer-file/write-file owner. The retained SWR 818896 provider predates that dependency, so receiver installation must select the new source and existing file owner explicitly. No install/start/stop hook is changed. If a native-readable source has duplicate rows, extra files or noncanonical head bytes that cannot survive native rewriting exactly, prepare refuses exact capture and leaves source plus partial destination intact. It never silently normalizes and calls that exact preservation.

Budgets are fixed refusal bounds: at most 16 MiB selected file bytes, 8192 files, 16384 directory/file entries, depth 8 below each selected type directory, and 10000 combined discovered records/heads/references. Copy also independently caps records plus heads at 10000. Inventory reads at most each previously observed file size plus one byte, uses a no-follow descriptor, checks descriptor identity, and rejects size drift. Selected regular files must have one link; symlinks, special files and unexpected checkpoint tiers/types/root entries are refused. Source data outside selected types is neither inventoried nor transmitted. Inventory entries and reference-obligation sets live only during the bounded call.

Failures throw native `StoreError`, existing corruption/filesystem errors, or `checkpoint-*` refusals. Nothing automatically deletes an interrupted target. A returned exact verification of a fully written target can resolve lost completion; a truly partial target fails verification and cannot be passed again to prepare. This proves byte identity at observation time, not that a previously interrupted final durability barrier completed. To reestablish write barriers after uncertain durability, retain that target and prepare into a new empty root under caller quiescence.
